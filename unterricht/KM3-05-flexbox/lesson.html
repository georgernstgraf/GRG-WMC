Lektion KM3-05 · Flexbox

Die Leiste denkt mit

Drei Karten nebeneinander, gleich hoch, gleiche Abstände — und auf dem Handy untereinander. Bisher war das Handarbeit. Ab jetzt ist es eine Eigenschaft am Elternelement.

Lektüre

Pflicht, vor dem Weiterlesen: CSS-Tricks — A Complete Guide to Flexbox (die Folie aus dem Unterricht, alle Eigenschaften auf einer Seite). Dazu zum Spielen: Flexbox Froggy — 24 Levels, jedes Level ist eine Regel.

Einstiegsfrage

Am Freitag soll der Merch-Stand online sein. Drei Produkte nebeneinander, alle drei gleich hoch, gleiche Abstände dazwischen. Der Preis klebt unten in der Karte, auch wenn eine Beschreibung drei Zeilen länger ist. Und auf dem Handy stehen die Karten untereinander.

Der naheliegende Weg: die Karten als inline-block mit width: 32%. Dann kostet jede Lücke Prozente, die letzte Karte rutscht in die nächste Zeile, und gleich hoch sind die Karten nur, wenn du jeder eine feste Höhe gibst. Genau die Höhe, die beim nächsten Text nicht mehr passt.

Geht das ohne Rechnen? Ja: Du sagst dem Elternelement, dass seine Kinder eine Leiste bilden. Ab da verteilt der Browser.

Das baust du in dieser Doppelstunde — den Kopf des Merch-Stands einer Band. Jeder Abschnitt ist eine Leiste, jede Leiste ein paar Zeilen CSS.

Dafür brauchst du kein Bild und keine Schriftart. Drei Platzhalter mit Rahmen genügen, um zu sehen, ob das Layout stimmt. Die Farbe kommt später.

Schritt 1 — Aus Kindern wird eine Leiste

Eine Eigenschaft am Container schaltet alles um:

.leiste {
    display: flex;   /* die Kinder bilden jetzt eine Leiste */
}

Vorher stapelten sich div-Kinder untereinander, weil Block-Elemente die volle Breite nehmen. Mit display: flex legt der Container seine Kinder in einer Reihe aus und verteilt den Platz selbst.

Dabei passieren drei Dinge, die du kennen musst:

1. Es gibt eine Hauptachse und eine Querachse. Standard ist flex-direction: row: Die Hauptachse läuft waagrecht nach rechts, die Querachse senkrecht. Alle Verteil-Eigenschaften arbeiten auf diesen zwei Achsen.

2. Nur direkte Kinder werden Items. Ein Absatz in einem div in der Leiste ist kein Item, sondern normaler Inhalt seines divs.

3. Die Kinder schrumpfen auf ihren Inhalt. Ein div ist als Item nicht mehr volle Breite breit, sondern so breit wie nötig. Und weil align-items standardmäßig stretch ist, werden alle Items gleich hoch — die Querachse streckt sie.

vorher (Block)            nachher (display: flex)
┌──────────────┐          ┌────┬────┬────┐
│     Kind 1   │          │ K1 │ K2 │ K3 │ ← gleiche Höhe,
├──────────────┤          └────┴────┴────┘   so hoch wie nötig
│     Kind 2   │             Hauptachse →
├──────────────┤
│     Kind 3   │
└──────────────┘
Achtung

Die Leiste ersetzt nicht width, sondern die Verteilung. Ein Kind mit width: 100% bleibt breit und drückt die anderen zusammen. Wer Flexbox nutzt, lässt die Breiten meist weg.

Schritt 2 — Richtung drehen, Umbruch erlauben

Zwei Eigenschaften bestimmen, wie die Leiste liegt und was passiert, wenn der Platz nicht reicht:

EigenschaftWertWirkung
flex-direction row (Standard) Hauptachse waagrecht, von links nach rechts
column Hauptachse senkrecht, von oben nach unten
flex-wrap nowrap (Standard) eine Zeile; reicht der Platz nicht, schrumpfen die Items
wrap neue Zeile, sobald der Platz nicht reicht

Die Falle: Mit flex-direction: column drehen sich beide Achsen mit. Die Hauptachse ist jetzt senkrecht — also richtet justify-content: center ab sofort senkrecht aus, und align-items waagrecht. Wer das verwechselt, sucht den Fehler an der falschen Stelle.

Aspektrowcolumn
Hauptachsewaagrecht →senkrecht ↓
justify-content verteiltwaagrechtsenkrecht
align-items richtet aussenkrechtwaagrecht
flex-basis meintBreiteHöhe

Die letzte Zeile ist der Grund, warum diese Tabelle mehr wert ist als ein Merksatz: Sobald du die Richtung drehst, ändert sich die Bedeutung von drei Eigenschaften gleichzeitig.

flex-wrap: wrap ist der Grund, warum der Produktstreifen überhaupt umbrechen kann: Mit flex-basis bekommt jede Karte eine Wunschbreite. Passen nicht alle in die Zeile, rutscht der Rest nach unten, statt sich zu quetschen. Bei 400 px Fensterbreite passt keine zweite Karte mehr daneben — der Streifen steht dann untereinander, ohne dass du dafür eine eigene Regel brauchst.

Kurzschreibweise, wenn beides zusammen gesetzt wird: flex-flow: row wrap;. Sie bedeutet genau flex-direction plus flex-wrap.

Was auf einem breiten Bildschirm gilt, muss auf einem schmalen nicht gelten. Dafür gibt es die Media Query: ein Block, der nur unterhalb einer Fensterbreite greift.

@media (max-width: 700px) {
    .hero { flex-direction: column; }   /* nur bis 700 px: untereinander */
}

Alles innerhalb der geschweiften Klammern gilt nur, solange das Fenster höchstens 700 px breit ist. Darüber bleibt der Block wirkungslos. Für den Produktstreifen brauchst du ihn nicht — der bricht schon durch wrap —, für den Hero und die Kopfleiste schon.

Schritt 3 — Verteilen auf der Hauptachse

justify-content beantwortet eine einzige Frage: Wie verteile ich den freien Platz entlang der Hauptachse? Die Items behalten ihre Größe, nur die Lücken dazwischen wachsen.

WertWo landet der freie Platz?Skizze (· = Platz)
flex-start (Standard)alles hinter den Items, sie kleben links[A][B][C]··········
flex-endalles davor, sie kleben rechts··········[A][B][C]
centergleich viel vor und hinter den Items·····[A][B][C]·····
space-betweenzwischen den Items; erstes und letztes am Rand[A]·····[B]·····[C]
space-aroundum jedes Item herum, halbe Lücken am Rand·[A]··[B]··[C]·
space-evenlyalle Lücken gleich groß, auch am Rand··[A]··[B]··[C]··

Für die Lücken zwischen den Items gibt es gap. Es setzt den Abstand zwischen den Items, nicht außen — genau das, was margin an jedem Kind mühsam nachbauen muss und was beim letzten Kind immer einen Rest lässt.

.streifen {
    display: flex;
    gap: 1rem;          /* 16px zwischen den Karten, nichts außen */
}
Merke

gap ersetzt margin an den Kindern. Wer beides setzt, bekommt doppelte Abstände — ein häufiger Grund für „warum ist die Lücke plötzlich so groß“.

Ein Sonderfall, der im Kopf bleibt: Füllen die Items die Zeile schon vollständig aus — etwa weil alle flex: 1 haben —, hat justify-content nichts zu verteilen. Sichtbar wird der Wert erst, wenn Platz übrig bleibt: bei Items ohne flex-grow, bei wenigen schmalen Karten, oder in der letzten Zeile nach einem Umbruch, die nicht mehr voll wird.

Worin unterscheiden sich space-between und space-around?

Schritt 4 — Ausrichten auf der Querachse

Nach der Hauptachse kommt die zweite Richtung. align-items richtet alle Items auf der Querachse aus — bei row also senkrecht.

WertWirkung (bei row)
stretch (Standard)alle Items so hoch wie die Zeile — gleich hohe Karten
flex-startoben ausgerichtet, jede Karte so hoch wie ihr Inhalt
flex-endunten ausgerichtet
centermittig — der Klassiker für Kopfleisten
baselinedie erste Textzeile liegt auf einer Linie

Mit align-self hebt ein einzelnes Kind die Entscheidung des Containers auf. Praktisch, wenn genau eine Karte oben kleben soll, während die anderen zentriert sind.

align-content klingt ähnlich, meint aber etwas anderes: Es verteilt mehrere Zeilen innerhalb des Containers. Bei einer einzigen Zeile hat es keine Wirkung — ein Klassiker unter den „warum tut sich nichts“-Momenten.

align-items: center        align-self: flex-start am 2. Kind
┌───────────────┐          ┌───────────────┐
│               │          │      ┌────┐   │
│ ┌───┐ ┌───┐   │          │ ┌───┐│ K2 │   │
│ │K1 │ │K2 │   │          │ │K1 │└────┘   │
│ └───┘ └───┘   │          │ └───┘         │
└───────────────┘          └───────────────┘
Achtung

Gleich hohe Karten brauchen kein height. Der Standard stretch macht das schon. Wer height: 100% schreibt, bekommt oft 0 oder eine abgeschnittene Karte, weil das Prozentmaß eine feste Elternhöhe verlangt.

Schritt 5 — Wachsen und Schrumpfen

Bis hierher haben die Items ihre Größe behalten. Jetzt verteilen wir auch die Größe. Drei Eigenschaften arbeiten zusammen:

EigenschaftFrage, die sie beantwortetStandard
flex-growWie viel vom überschüssigen Platz nimmt es?0
flex-shrinkWie stark darf es schrumpfen, wenn Platz fehlt?1
flex-basisWelche Größe hat es vor der Verteilung?auto

Statt drei Zeilen schreibt man meist die Kurzform flex. Sie heißt immer flex: grow shrink basis:

flex: 1;              /* = 1 1 0%    : gleicher Anteil am Ganzen */
flex: 2;              /* = 2 1 0%    : doppelter Anteil */
flex: auto;           /* = 1 1 auto  : wächst, Basis ist der Inhalt */
flex: none;           /* = 0 0 auto  : bleibt genau so groß */
flex: 1 1 18rem;      /* Wunschbreite 18rem, danach gerecht verteilt */

Rechnen wir einmal: Ein Streifen ist 600 px breit, gap: 15px zwischen drei Karten. Die Karten haben flex: 1 1 90px. Abzüglich der zwei Lücken bleiben 570 px. Die drei Wunschbreiten kosten 270 px, also sind 300 px übrig. Die verteilen sich zu gleichen Teilen: jede Karte wird 90 + 100 = 190 px breit.

Achtung

flex-basis wirkt auf der Hauptachse. Bei flex-direction: column ist das die Höhe: Aus flex: 1 1 18rem wird eine Ausgangshöhe von 18rem. Mit flex-shrink: 1 darf die Karte darunter gehen, aber sie startet bei 18rem — der Grund, warum eine Karte im Hochformat plötzlich einen leeren Streifen mitschleppt.

Eine letzte Grenze: Ein Item schrumpft nie unter seinen Inhalt, solange min-width auf auto steht (der Standard). Ein Bild oder ein langes Wort hält die Karte also breit. Wenn es wirklich schrumpfen soll, hilft min-width: 0 am Item.

Schritt 6 — Reihenfolge und der Automatik-Rand

Zwei Werkzeuge bleiben, und beide sind kleine Zaubertricks mit großem Nutzen.

order ändert die visuelle Reihenfolge der Items. Der Standardwert ist 0, kleinere Werte rutschen nach vorn (auch negative), größere nach hinten. Das HTML bleibt unangetastet — und genau da liegt die Gefahr: Wer mit order die Reihenfolge umdreht, ändert die Tabulator-Reihenfolge nicht. Für Tastatur und Screenreader bleibt es die alte Reihenfolge.

margin: auto ist in einer Flexbox mächtiger als sonst: Ein Automatik-Rand frisst den gesamten freien Platz auf seiner Seite. Deshalb ist der Standardtrick für die Kopfleiste genau eine Zeile:

.nav { margin-left: auto; }   /* frisst den Platz links: rutscht nach rechts */

Dasselbe in beide Richtungen — margin: auto an einem Item — zentriert es waagrecht und senkrecht. Das ist der kürzeste Weg, eine Karte in einem Container zu zentrieren.

Antwort auf die Einstiegsfrage

Die Leiste braucht display: flex und gap. Gleich hoch werden die Karten durch den Standard align-items: stretch, gleiche Breiten durch flex: 1. Der Preis klebt unten, weil die Karte selbst eine Spalte ist (flex-direction: column) und der Preis margin-top: auto bekommt. Der Umbruch im Streifen ist flex-wrap: wrap; die Media Query braucht nur der Hero, der untereinander klappt. Keine feste Höhe, keine Prozentrechnung.

Typische Fehler

Fehler 1 — Zentrieren auf der falschen Achse

/* Karte soll senkrecht mittig sitzen — tut sie nicht: */
.leiste { display: flex; justify-content: center; }

/* Richtig: senkrecht ist die Querachse. Sichtbar wird das erst, wenn
   der Container höher ist als die Karte (padding oder feste Höhe). */
.leiste { display: flex; align-items: center; }

Fehler 2 — display: flex am Kind statt am Container

.karte { display: flex; }    /* ordnet nur den INHALT der Karte */
.streifen { display: flex; } /* ordnet die Karten selbst */

Fehler 3 — gleiche Höhe mit height erzwingen

.karte { height: 100%; }     /* 0 oder abgeschnitten */
/* Standard reicht: align-items: stretch */

Fehler 4 — flex: 1 ohne Flex-Container

/* .streifen hat kein display: flex */
.karte { flex: 1; }   /* wirkungslos: kein Elternteil ist Flexbox */

Fehler 5 — gap und margin doppelt

.streifen { gap: 1rem; }
.karte { margin: 0 1rem; }   /* doppelte Lücke, außen ein Rest */

Fehler 6 — flex-basis in der Spalte für die Breite gehalten

.spalte { display: flex; flex-direction: column; }
.karte { flex: 1 1 18rem; }  /* 18rem ist hier die HÖHE, nicht die Breite */

Fehler 7 — order als Reparatur für schlechtes HTML

/* Optisch passt es, für Tastatur und Screenreader nicht: */
.knopf { order: -1; }  /* wird zuerst gesehen, zuletzt erreicht */
