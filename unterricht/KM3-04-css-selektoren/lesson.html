Lektion KM3-04 · CSS-Selektoren

Der Selektor ist eine Adresse

Wie du ein Element triffst, ohne es anzufassen — und warum dieselbe Adresse zwei verschiedene Elemente meinen kann.

Lektüre

Pflicht, vor dem Weiterlesen: MDN — CSS-Selektoren (Übersicht mit allen Familien). Dazu zum Spielen: CSS Diner — 32 Levels, jede Aufgabe ist ein Selektor.

Einstiegsfrage

Am Freitag soll die Speisekarte fertig sein. Die Tabelle soll Zebra-Streifen haben, der letzte Eintrag der Getränkeliste soll anders aussehen, und der Bestellknopf soll erst reagieren, wenn das Häkchen „AGB gelesen" gesetzt ist.

Der naheliegende Weg: jede Zeile einzeln ansprechen. Bei zehn Zeilen geht das. Bei vierzig Zeilen hast du vierzig class-Namen im HTML — und beim nächsten neuen Gericht schreibst du sie wieder.

Geht das auch ohne Anfassen? Ja: Ein Selektor ist eine Adresse, die auf ein Element zeigt. Wer die Adresse richtig schreibt, muss das HTML nicht anfassen.

Ziel-Artefakt

Das ist dein Übungsobjekt für die nächsten 90 Minuten: das Selektoren-Labor (öffnet im selben Tab). Eine Seite mit Tabelle, Listen, Formular und Links — jede Regel im Stylesheet nennt den Selektor, den sie verwendet.

/* So sieht eine Regel im Labor aus — Kommentar = Selektor */
table.labor tbody tr:nth-child(odd) {
    background: #f1f3fb;     /* Zeilen 1, 3, 5, 7, 9 */
}

Arbeitsweise: Seite im Browser öffnen, F12 drücken, Elements wählen, ein Element anklicken — rechts unter Styles steht, welche Regel greift und welche von einer stärkeren verdrängt wird (durchgestrichen).

Danach änderst du in demo.css einen Selektor, lädst neu und siehst den Unterschied. Genau das ist die Übung.

Schritt 1 — Die fünf Grundformen

Jeder Selektor beginnt mit einem von fünf Mustern. Alles Weitere in dieser Lektion ist eine Verfeinerung davon.

FormBeispielTrifft
Elementpalle Absätze
Klasse.hinweisalle Elemente mit class="hinweis"
ID#introdas Element mit id="intro"
Universal*jedes Element
Gruppeh1, h2alle h1 und alle h2

Die Klasse ist der Normalfall: Sie darf mehrfach vorkommen und ist für Styling gedacht. Die ID ist für einmalige Ankerziele gedacht — und sie wiegt in der Rangordnung (Schritt 7) am schwersten.

Achtung

Das Komma ist ein ODER, kein UND. h2, p heißt: jedes h2 und jeder p — nicht „p in h2". Die Reihenfolge im Komma ändert nichts.

Eine Regel soll genau die Absätze mit der Klasse hinweis formatieren — und sonst nichts. Welche Selektoren tun das?
Welche Selektoren treffen das Element <p class="hinweis gross" id="intro">?
Was stimmt über die Gruppe h2, p { … }?
Welche Spezifität bringt der Universal- Selektor * in eine Regel?

Schritt 2 — Kombinatoren: vier Wege nach innen und zur Seite

Ein Selektor allein trifft oft zu viel. Kombinatoren verfeinern die Adresse — drei davon zeigen nach innen (Nachfahre, Kind), zwei zur Seite (Nachbar, Geschwister).

ZeichenNameBedeutung am Beispiel
LeerzeichenNachfahrearticle p — jeder p irgendwo in article
>Kindarticle > p — nur direkte Kinder
+direkter Nachbarh2 + p — der eine p direkt danach
~allgemeiner Geschwisterh2 ~ p — alle p danach, gleiche Ebene

Der Klassiker: .a .b und .a.b sehen ähnlich aus, meinen aber Verschiedenes. Das Leerzeichen sucht ein Element in einem anderen; der Punkt ohne Leerzeichen verlangt zwei Klassen am selben Element.

.karte .marke   /* ein Element .marke IRGENDWO in .karte */
.karte.marke    /* EIN Element, das beide Klassen trägt */
.karte > .marke /* .marke als direktes Kind von .karte */
Ein <p> steckt zwei Ebenen tief in einem <article>, in einem <div>. Welche Selektoren treffen ihn?
Drei Absätze stehen unter einer h2. Was trifft h2 + p?
In einer Liste trägt der zweite Eintrag die Klasse marke. Was trifft li.marke ~ li?
Welche zwei Schreibweisen meinen dasselbe Element?

Schritt 3 — Struktur: zählen statt Klassen vergeben

Diese Familie fragt nach der Position eines Elements in seinem Elternelement. Du brauchst dafür kein einziges zusätzliches Attribut im HTML.

PseudoklasseFragt nach
:first-childerstes Kind des Elternelements
:last-childletztes Kind
:only-childeinziges Kind (keine Geschwister)
:nth-child(An+B)Position von vorn, z. B. 2n+1, -n+3
:nth-last-child(n)Position von hinten
:first-of-type …wie oben, aber nur unter Geschwistern desselben Tags
:emptyElement ohne jeden Inhalt

:nth-child(2n) trifft die geraden Positionen (2, 4, 6 …), 2n+1 die ungeraden. -n+3 liest sich „bis drei": 1, 2, 3. Und :nth-child(0) trifft nie etwas — die Zählung beginnt bei 1.

Merke

:nth-child zählt alle Kinder, nicht nur die des eigenen Tags. Steht in einem Container zuerst eine h3, ist der erste p das zweite Kind. Wer nur die Absätze zählen will, nimmt :nth-of-type.

Eine Liste hat fünf Einträge. Welche trifft li:nth-child(2n)?
Was trifft tr:nth-child(-n+3) in einer Tabelle mit acht Zeilen?
Ein Container enthält zuerst eine <h3>, dann zwei <p>. Was trifft p:first-of-type?
Welche Aussagen über die Struktur-Pseudoklassen stimmen?

Schritt 4 — Zustand: was der Benutzer gerade tut

Diese Pseudoklassen fragen nicht nach dem Aufbau, sondern nach dem Moment: Ist das Häkchen gesetzt? Hat das Feld den Fokus? Ist der Link gerade das Sprungziel?

PseudoklasseGilt, wenn …
:hoverder Zeiger darüber ist (nur mit Maus)
:focus-visibleder Fokus per Tastatur dorthin kam
:checkedHäkchen oder Radiobutton gesetzt ist
:disabled / :requireddas Feld gesperrt bzw. Pflicht ist
:invalid / :placeholder-shownder Wert ungültig ist bzw. noch der Platzhalter steht
:targetdas Element ist das Ziel des aktuellen Sprungmarken-Ankers

Der stärkste Fall ist :checked + label: Das Häkchen selbst bleibt unsichtbar klein, aber das Label daneben wird fett und grün. Kein JavaScript, keine zusätzliche Klasse — der Zustand des Inputs steuert die Darstellung seines Nachbarn.

Dazu kommen vier Logik-Pseudoklassen, die Selektoren kombinieren:

:not(.aktiv)        /* alles außer den Elementen mit .aktiv */
:is(h2, h3)         /* h2 oder h3 — Gewicht zählt wie der schwerste Teil */
:where(h2, h3)      /* dasselbe, aber mit Gewicht 0 */
.kasten:has(img)    /* ein .kasten, der ein img ENTHÄLT */

:is() und :where() unterscheiden sich nur in der Rangordnung. :where() ist die höfliche Variante für Bibliotheken: Sie lässt sich später leicht überschreiben.

Ein Häkchen soll das Label direkt daneben hervorheben. Welcher Selektor tut das?
Worin unterscheiden sich :focus und :focus-visible?
Was macht .kasten:has(img)?
Welche Aussagen über :not, :is und :where stimmen?

Schritt 5 — Attribute: Daten am Element auswerten

Jedes Element trägt Attribute: href, type, lang, id, class — und eigene data-*. Selektoren können sie prüfen, ohne dass du eine Klasse vergeben musst.

SchreibweisePrüftBeispiel
[attr]Attribut ist vorhanden[data-status]
[attr="wert"]genauer Wert[data-status="offen"]
[attr^="…"]Wert beginnt damit[href^="https"]
[attr$="…"]Wert endet damit[href$=".pdf"]
[attr*="…"]Wert enthält es irgendwo[class*="karte"]
[attr~="…"]es ist ein ganzes Wort im Wert[class~="karte"]
[attr|="…"]Wert ist es oder beginnt mit „es-"[lang|="de"]

[class~="karte"] und [class*="karte"] sind der häufigste Verwechslungspunkt: Die Tilde verlangt das Wort ganz, der Stern begnügt sich mit einem Teilstück. Aus class="karte-extragross" wird also nur mit dem Stern ein Treffer.

Was trifft a[href$=".pdf"]?
Welche Aussagen über [class~="karte"] und [class*="karte"] stimmen?
Welche Aussagen über [data-status] und [data-status="offen"] stimmen?
Welche Schreibweise prüft den Anfang eines Attributwerts?

Schritt 6 — Pseudoelemente: Teile, die es im HTML nicht gibt

Pseudoelemente schreibst du mit zwei Doppelpunkten. Sie adressieren einen Teil eines Elements — oder erzeugen einen, der nicht im Quelltext steht.

PseudoelementZiel
::before / ::aftererzeugter Inhalt vor bzw. nach dem Elementinhalt
::first-letterder erste Buchstabe
::first-linedie erste Zeile, wie sie gerade umbrochen wird
::markerdas Aufzählungszeichen einer Liste
::selectionder mit der Maus markierte Text
::placeholderder Platzhaltertext eines Eingabefelds

::before und ::after brauchen content. Ohne diese Eigenschaft existiert das Pseudoelement nicht — es erscheint nichts, und das ist der häufigste „warum sehe ich nichts"-Fall.

.zaehler::before {
    content: "Station " counter(zaehler) ": ";  /* Text entsteht im CSS */
}

Der erzeugte Text steht nicht im HTML-Quelltext. Für Bildschirmleser ist er deshalb heikel: Was inhaltlich zählt, gehört ins HTML; was nur Dekoration ist, darf ins CSS.

Du schreibst .karte::before { color: red; } — und siehst nichts. Woran liegt es?
Welche der folgenden sind echte Pseudoelemente?
Warum schreibt man ::before mit zwei Doppelpunkten?
Welche Aussagen über Pseudoelemente stimmen?

Schritt 7 — Wer gewinnt? Spezifität und Kaskade

Mehrere Regeln treffen dasselbe Element — welche gilt? Die Antwort steht in drei Stufen: Rangordnung, Reihenfolge, !important.

SchreibweiseGewichtBeispiel
Element, Pseudoelement0-0-1p, ::before
Klasse, Attribut, Pseudoklasse0-1-0.tacho, [lang], :hover
ID1-0-0#tacho
style-Attributhöher als jede IDstyle="color: red"

Die drei Zahlen werden von links nach rechts verglichen: Eine ID schlägt beliebig viele Klassen. Bei gleichem Gewicht gewinnt die später notierte Regel — und !important schlägt beides.

Deshalb ist !important die Ausnahme: Es hebelt die Rangordnung aus, und danach hilft nur noch mehr !important. Für Kurs-CSS gilt: erst gar nicht anfangen.

Merke

Die DevTools zeigen die Rangordnung: Verdrängte Deklarationen stehen durchgestrichen da, die stärkste Regel steht oben. Wer streitet, schaut zuerst dorthin.

Zwei Regeln treffen denselben Absatz: #tacho { color: orange; } und .tacho { color: blue; }. Welche Farbe gewinnt?
Zwei Regeln haben genau dasselbe Gewicht und treffen dasselbe Element. Was gilt?
Welche Gewichte stimmen?
Was stimmt über !important?

Ausprobieren: Im Labor steht derselbe Absatz unter vier Regeln. Lösche im HTML das style-Attribut, dann die ID-Regel, dann die Klassenregel — die Farbe wandert Stufe für Stufe.

Typische Fehler

Fehler 1 — :nth-child mit :nth-of-type verwechselt

/* Container: h3, p, p — der erste p ist das ZWEITE Kind */
p:nth-child(1) { }   /* trifft nichts: Kind 1 ist die h3 */
p:nth-of-type(1) { } /* trifft den ersten p */

Fehler 2 — Leerzeichen, wo keines hingehört

li .marke { }  /* .marke IRGENDWO in einem li */
li.marke  { }  /* ein li, das selbst .marke ist */

Fehler 3 — + und ~ vertauscht

h2 + p { }  /* genau der nächste Absatz */
h2 ~ p { }  /* alle Absätze danach */

Fehler 4 — ::before ohne content

.karte::before { color: red; }          /* unsichtbar */
.karte::before { content: "→"; }        /* sichtbar */

Fehler 5 — [class*=…] statt [class~=…]

[class~="karte"] { }  /* trifft class="karte" — nicht "karte-gross" */
[class*="karte"] { }  /* trifft beides */

Fehler 6 — ID als Styling-Werkzeug

#bestellknopf { background: teal; }  /* 1-0-0: kaum überschreibbar */
.bestellknopf { background: teal; }  /* 0-1-0: wartbar */
