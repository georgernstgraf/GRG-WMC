Lektion KM3-06 · CSS Grid

Zwei Richtungen auf einmal

Drei Karten nebeneinander waren eine Leiste. Jetzt kommt ein ganzes Seitengerüst: Kopf und Fuß über die volle Breite, links die Navigation, rechts die Termine. Und die Karten ordnen sich selbst.

Lektüre

Pflicht, vor dem Weiterlesen: CSS-Tricks — A Complete Guide to Grid (alle Eigenschaften auf einer Seite, englisch, mit Bildern). Dazu zum Spielen: Grid Garden — 28 Levels, jedes Level ist eine Eigenschaft.

Einstiegsfrage

Der Merch-Stand bekommt eine Termine-Seite. Sie hat vier Zonen: oben eine Kopfleiste über die ganze Breite, links eine schmale Spalte mit dem Tourplan, rechts die Terminkarten. Unten folgt eine Fußzeile — wieder über die ganze Breite.

Mit dem Werkzeug aus der letzten Stunde geht das so: außen eine senkrechte Leiste für Kopf, Mittelteil und Fuß. Der Mittelteil ist eine waagrechte Leiste für Plan und Karten. Die Karten stehen in einer dritten Leiste, die umbricht. Jede Ebene hat ihre eigene Achse und rechnet ihre Breiten selbst.

Das funktioniert, ist aber ein Flexbox-Sandwich: Drei verschachtelte Leisten, die voneinander nichts wissen. Der Kopf läuft nur dann über die volle Breite, wenn du die Breite auf jeder Ebene erneut angibst. Und auf dem Handy baust du die Verschachtelung per Media Query um.

Geht das in einem Schritt? Ja: Du beschreibst dem Elternelement ein Raster aus Zeilen und Spalten. Danach klebt der Kopf an der oberen Kante, der Fuß an der unteren — ohne dass dazwischen etwas verschachtelt ist.

Ziel-Artefakt

Das baust du in dieser Doppelstunde — die Termine-Seite des Merch-Stands. Ein Raster trägt das Gerüst, ein zweites ordnet die Karten.

Schritt 1 — Aus einem Container wird ein Raster

Eine Eigenschaft am Container schaltet um:

.seite {
    display: grid;   /* Zeilen UND Spalten, nicht nur eine Leiste */
}

Ab hier hat der Container ein Raster. Wie bei Flexbox werden nur die direkten Kinder zu Grid-Items; ein Absatz in einem div bleibt normaler Inhalt seines divs.

Drei Dinge sind neu gegenüber der Leiste:

1. Es gibt keine Haupt- und Querachse, die sich drehen. Waagrecht und senkrecht sind von Anfang an zwei gleichwertige Richtungen — Spalten und Zeilen.

2. Die Kinder fließen von selbst. Du schreibst kein flex an die Karten. Der Browser setzt sie zeilenweise in die nächsten freien Zellen: erst nach rechts, am Zeilenende weiter in der nächsten Zeile.

3. Die Zellen bleiben, auch wenn sie leer sind. Ein Raster mit drei Spalten und nur zwei Karten zeigt zwei Karten und eine leere Zelle. Das Raster wird dadurch weder schmaler noch wachsen die Karten hinein.

display: flex                display: grid
┌──────────────────┐         ┌─────┬─────┬─────┐
│ K1 K2 K3         │         │ K1  │ K2  │ K3  │
└──────────────────┘         ├─────┼─────┼─────┤
  eine Leiste,               │ K4  │     │     │
  die Kinder bestimmen       └─────┴─────┴─────┘
  ihre Breite selbst          feste Spalten,
                              feste Zeilen

FrageFlexboxGrid

Achtung

Ohne Spaltenangabe hat ein Raster genau eine Spalte: Die Kinder stehen untereinander, wie Block-Elemente. display: grid alleine sieht also erst einmal nach nichts aus. Erst grid-template-columns macht daraus mehrere Spalten — Schritt 2.

Noch ein Wort zu den Namen, die in Schritt 4 auftauchen: Sie sind frei wählbar. Sie haben nichts mit HTML-Tags zu tun, dürfen mehrfach vorkommen — genau dadurch entsteht ein breiter Bereich — und dürfen nicht mit einem Punkt beginnen oder eine Ziffer sein.

Schritt 2 — Spalten und Zeilen beschreiben

Die Spalten stehen am Container, in einer Zeile, von links nach rechts. Jede Angabe ist eine Spalte:

.seite {
    display: grid;
    grid-template-columns: 12rem 1fr;   /* Navigation, dann der Rest */
    gap: 1.5rem;                        /* Abstand zwischen den Zellen */
}

12rem ist eine feste Breite. 1fr heißt „ein freier Anteil“ — der Platz, der nach gap und den festen Spalten übrig bleibt, wird unter allen fr-Spalten aufgeteilt.

Rechnen wir einmal: Ein Container ist 600 px breit, gap: 0, die Spalten sind 2fr 3fr 1fr. Alle Angaben sind fr, also wird die ganze Breite geteilt: 2 + 3 + 1 = 6 Anteile zu je 100 px. Die Spalten werden 200 px, 300 px und 100 px breit.

Kommt gap dazu, wird es vorher abgezogen. Ein Container ist 640 px breit, gap: 20px, die Spalten sind repeat(3, 1fr). Für die Spalten bleiben 640 − 2 × 20 = 600 px, also je 200 px. Die Lücke gehört dem Container, nicht der Spalte.

repeat() spart Tipparbeit, wenn sich Angaben wiederholen. Es funktioniert auch mit Mustern:

grid-template-columns: repeat(3, 1fr);      /* 1fr 1fr 1fr */
grid-template-columns: repeat(2, 80px 1fr); /* 80px 1fr 80px 1fr */

Zeilen beschreibst du genauso mit grid-template-rows. Für das Seitengerüst reicht eine Zeile mit drei Höhen:

.seite {
    grid-template-rows: auto 1fr auto;  /* Kopf so hoch wie nötig,  */
    min-height: 100dvh;                 /* Mitte füllt den Rest,   */
}                                       /* Fuß wieder so hoch wie nötig */

auto heißt „so groß wie der Inhalt“. 1fr nimmt den Rest der Höhe. 100dvh ist die Höhe des sichtbaren Fensterbereichs, d steht für „dynamic“: Sie schrumpft mit, wenn auf dem Handy die Adressleiste Platz nimmt. Mit min-height: 100dvh ist die Seite mindestens so hoch wie das Fenster — deshalb sitzt der Fuß unten, auch wenn wenig Inhalt da ist.

Die Zeilen musst du aber nicht vorher kennen. Legst du weniger Zeilen fest als Kinder vorhanden sind, erzeugt der Browser implizite Zeilen. Deren Höhe steuerst du mit grid-auto-rows:

.produkte {
    grid-auto-rows: minmax(8rem, auto);  /* mindestens 8rem, sonst Inhalt */
}

minmax() setzt eine Unter- und eine Obergrenze. minmax(8rem, auto) heißt: nie kleiner als 8rem, nach oben offen für den Inhalt. Das ist der Standard für Kartenraster, in denen eine Beschreibung länger ist als die andere.

Merke

gap setzt den Abstand zwischen den Zellen, nichts außen. Es ersetzt margin an den Kindern — wer beides setzt, bekommt doppelte Lücken. Das kennst du schon aus der Flexbox.

Schritt 3 — Zellen von Hand belegen

Bis hierher hat der Browser die Kinder selbst verteilt. Jetzt greifst du ein — mit den Linien zwischen den Zellen. Ein Raster hat immer eine Linie mehr als Spalten:

Spalten:    [   1   ][   2   ][   3   ]
Linien:    1        2        3        4

Die Linien werden ab 1 durchnummeriert, von links nach rechts bzw. von oben nach unten. Ein Kind bekommt zwei Linien: die, an der es beginnt, und die, an der es endet.

.kopf {
    grid-column: 1 / 3;   /* von Linie 1 bis Linie 3: Spalten 1 und 2 */
}

.fuss {
    grid-column: 1 / -1;  /* -1 ist die letzte Linie: ganze Breite */
}

Die Falle: Die zweite Zahl ist die Endlinie, nicht die Anzahl der Zellen. grid-column: 1 / 3 deckt zwei Spalten, grid-column: 1 / 2 nur eine. Die Endlinie gehört nicht mehr zum Element — genau wie beim Zuschneiden: Du schneidest an der Linie.

Für das Seitengerüst ist -1 die praktische Abkürzung: Sie meint immer die letzte Linie, egal wie viele Spalten du später dazunimmst. grid-row: 1 / 3 funktioniert senkrecht genauso.

Wenn du die Zellen nicht zählen willst, sagst du stattdessen span:

.karte-breit {
    grid-column: span 2;   /* zwei Zellen ab der Stelle, die Grid zuteilt */
    grid-row: span 2;      /* zwei Zeilen hoch */
}

span ist der Unterschied zwischen „zwei Zellen ab hier“ und „genau hier“. Die Kurzform mit Linien ist dann sinnvoll, wenn die Lage im Raster wichtig ist — etwa eine Karte, die oben rechts über zwei Zeilen laufen soll:

.werbung {
    grid-column: 3;        /* Spalte 3 (Linie 3 bis Linie 4) */
    grid-row: 2 / 4;       /* Zeilen 2 und 3 */
}
Achtung

Zeilen- und Spaltennummern zählen die Linien des Rasters, nicht die Kinder. Wer die Kinder zählt, landet eine Zelle daneben — und weil das Raster trotzdem gültig ist, gibt es keine Fehlermeldung, nur ein falsches Bild.

Schritt 4 — Bereiche benennen

Liniennummern funktionieren, sind aber schwer zu lesen: Wer grid-column: 2 / 5 sieht, muss zählen. Für ein ganzes Seitengerüst gibt es etwas Besseres — du zeichnest das Layout mit Namen:

.seite {
    display: grid;
    grid-template-columns: 12rem 1fr;
    grid-template-areas:
        "kopf  kopf"
        "nav   main"
        "fuss  fuss";
    gap: 1rem;
}

.kopf { grid-area: kopf; }
.nav  { grid-area: nav;  }
.main { grid-area: main; }
.fuss { grid-area: fuss; }

Jede Zeile in Anführungszeichen ist eine Rasterzeile. Jeder Name ist eine Zelle. Gleiche Namen, die aneinander liegen, werden zu einem Bereich zusammengefasst — deshalb spannt kopf über beide Spalten.

Drei Regeln entscheiden, ob die Vorlage gültig ist:

1. Jede Zeile hat gleich viele Namen. Eine Zeile mit einem Namen mehr oder weniger macht die ganze Vorlage ungültig. Wie breit das Raster wirklich ist, entscheidet grid-template-columns; die Vorlage muss dazu passen, sonst bleiben Spalten ohne Namen.

2. Jeder Bereich ist ein Rechteck. Ein L-förmiger Bereich „um die Ecke“ ist nicht erlaubt. Der Fehler ist still: Die gesamte grid-template-areas-Angabe wird ungültig, die Bereiche fallen weg, und die Kinder landen an Stellen, die du nie geplant hast. Es gibt keine Fehlermeldung.

3. Leere Zellen bekommen einen Punkt. In einem dreispaltigen Raster lässt "nav main ." die dritte Zelle frei. Ein Name, der in der Vorlage fehlt, platziert sein Element automatisch: Es landet in der nächsten freien Zelle, oft in einer neuen Zeile.

Der große Gewinn: Auf schmalen Bildschirmen schreibst du die Vorlage neu, ohne das HTML anzufassen. Die Reihenfolge kann sich dabei ändern, weil die Bereiche über ihre Namen angesprochen werden:

@media (max-width: 720px) {
    .seite {
        grid-template-columns: 1fr;
        grid-template-areas:
            "kopf"
            "nav"
            "main"
            "fuss";
    }
}

Unter 720 px gibt es nur eine Spalte, und die Vorlage schreibt die Bereiche untereinander. Die Navigation steht damit zwischen Kopf und Inhalt — im HTML steht sie an derselben Stelle wie vorher. Die Vorlage ordnet also nur die Darstellung um.

Die Tücke ist dieselbe wie bei order: Weicht die Darstellung von der Dokumentreihenfolge ab, tabbst du weiter durch die alte Reihenfolge, und Screenreader lesen sie so vor. Wähle die Mobile-Vorlage deshalb so, dass sie der Lese-Reihenfolge im HTML folgt — oder bring das HTML gleich in die Reihenfolge, die du willst.

Merke

Die Vorlage ist eine ASCII-Zeichnung des Layouts. Wer sie ansieht, erkennt die Seite — ohne CSS zu lesen. Das ist der Grund, warum sie sich auch für die mündliche Prüfung lohnt: Du kannst dein Layout erklären, indem du es aufmalst.

Schritt 5 — Das Raster rechnet selbst

Bis hierher stand die Spaltenzahl fest. Für die Terminkarten willst du etwas anderes: so viele Spalten, wie hineinpassen. Dafür kombinierst du repeat() mit auto-fit und minmax():

.produkte {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(14rem, 1fr));
    gap: 1rem;
}

Lies es von innen nach außen: minmax(14rem, 1fr) ist eine Spalte, die mindestens 14rem breit ist und dann wächst. auto-fit heißt: Bilde so viele solche Spalten, wie nebeneinander passen. repeat() wiederholt das Muster.

Rechnen wir einmal: Ein Fenster ist 800 px breit, gap: 16px, minmax(180px, 1fr). Vier Spalten brauchen 4 × 180 + 3 × 16 = 768 px — das passt. Fünf Spalten bräuchten 5 × 180 + 4 × 16 = 964 px — das passt nicht. Also entstehen vier Spalten; die übrigen 32 px werden gleichmäßig verteilt: jede Spalte wird 188 px breit.

Das Ergebnis ist ein Kartenraster ohne Media Query: Bei jedem Fenster entstehen so viele Spalten, wie die Mindestbreite zulässt. Auf dem Handy ist das eine Spalte, auf dem Beamer sind es vier — mit derselben Regel.

Was macht aber auto-fit mit leeren Spalten? Es entfernt sie. Enthält das Raster nur zwei Karten, bleiben bei 800 px zwei Spalten zu je 392 px übrig — die zwei leeren Spuren verschwinden. auto-fill täte das Gegenteil: Es behielte vier Spuren zu 188 px und ließe die letzten zwei leer. Der Unterschied ist nur sichtbar, wenn weniger Karten als Spaltenplätze da sind.

Antwort auf die Einstiegsfrage

Das Seitengerüst ist ein Raster mit drei Zeilen und zwei Spalten; kopf und fuss stehen in der Vorlage in beiden Spalten. Die Karten liegen in einem zweiten Raster im main-Bereich und holen sich ihre Spaltenzahl mit repeat(auto-fit, minmax(14rem, 1fr)). Kein Sandwich aus Leisten, keine Prozentrechnung, und die Media Query schreibt nur Vorlage und Spaltenzahl um — nicht die Struktur.

Schritt 6 — Ausrichten und entscheiden

Im Raster gibt es zwei Dinge, die ausgerichtet werden können: der Inhalt in seiner Zelle und das Raster als Ganzes im Container. Dafür gibt es zwei Familien von Eigenschaften.

Ebenewaagrechtsenkrechtbeides
Inhalt in der Zelle (Container) justify-items align-items place-items
ein einzelnes Kind justify-self align-self place-self
das ganze Raster im Container justify-content align-content place-content

Die Merkregel ist hier einfacher als bei der Flexbox, weil die Achsen feststehen: justify heißt immer waagrecht (in der Schreibrichtung), align immer senkrecht. Bei Flexbox hing das von flex-direction ab — bei Grid nicht.

.karte {
    display: grid;
    place-items: center;   /* Inhalt waagrecht UND senkrecht mittig */
}

Die dritte Zeile der Tabelle ist der Stolperstein. justify-content: center zentriert nicht den Inhalt der Zellen, sondern das ganze Raster — und nur dann, wenn das Raster schmaler ist als sein Container. Ein Raster aus repeat(3, 100px) in einem 600 px breiten Container ist 300 px breit; justify-content: center schiebt es in die Mitte, 150 px von jeder Seite.

Für Zeilen gilt derselbe Gedanke mit align-content: Sind die Zeilen zusammen niedriger als der Bereich, verteilt diese Eigenschaft die freie Höhe. Mit align-content: start beginnen die Karten oben, statt sich über die ganze Höhe zu strecken — genau das brauchst du im Termine-Raster.

Für den Alltag heißt das: items ist der Normalfall, content die Ausnahme. Wer den Inhalt einer Zelle mittig haben will und justify-content schreibt, sieht oft keine Änderung. Der Grund: Das Raster füllt den Container schon aus, also gibt es nichts zu verteilen.

Und wann nimmst du was? Die Entscheidung ist eine Frage an das Layout, nicht an den Geschmack:

Wenn …dann
die Anordnung in einer Richtung fließen soll (Leiste, Button-Gruppe, Karteninhalt)Flexbox
Zeilen und Spalten aufeinander Bezug nehmen (Gerüst, Kalender, Galerie)Grid
die Spaltenzahl aus der Breite folgen soll Grid mit auto-fit und minmax()
die Elemente ihre Größe aus dem Inhalt ziehen Flexbox

In der Praxis arbeitest du mit beiden: Grid für das Gerüst, Flexbox im Innenleben. Eine Karte ist ein Grid-Item und ein Flex-Container für ihre Überschrift und den Preis — die Werkzeuge schließen einander nicht aus.

Achtung

Grid-Items werden standardmäßig in beiden Richtungen gestreckt. Eine Karte füllt also ihre Zelle, auch wenn der Inhalt kleiner ist. Wer das nicht will, setzt align-items: start am Container — oder align-self: start am einzelnen Kind.

Typische Fehler

Fehler 1 — Die Endlinie als Zellenzahl gelesen

/* Soll zwei Spalten decken, deckt aber eine: */
.karte { grid-column: 1 / 2; }

/* Richtig: die zweite Zahl ist die Linie HINTER der letzten Zelle. */
.karte { grid-column: 1 / 3; }   /* Spalten 1 und 2 */

Fehler 2 — Ein Bereich „um die Ecke“

/* nav läuft links durch und unten weiter — L-Form: */
grid-template-areas:
    "kopf kopf"
    "nav  main"
    "nav  nav";    /* nav ist L-förmig → ganze Vorlage ungültig */

Fehler 3 — Ungleich lange Zeilen in der Vorlage

grid-template-areas:
    "kopf kopf"
    "nav main"
    "fuss";        /* dritte Zeile hat nur einen Namen → ungültig */

Fehler 4 — 1fr für „100 %“ gehalten

/* Ein langes Wort dehnt die erste Spalte: 1fr hat ein Mindestmaß
   von "auto", also mindestens die Breite des Inhalts. */
.raster { grid-template-columns: 1fr 1fr; }

/* Richtig, wenn beide Spalten wirklich gleich sein sollen: */
.raster { grid-template-columns: repeat(2, minmax(0, 1fr)); }

Fehler 5 — display: grid am Kind statt am Container

.karte { display: grid; }     /* ordnet nur den INHALT der Karte */
.raster { display: grid; }    /* ordnet die Karten selbst */

Fehler 6 — justify-content für die Zelle gehalten

/* Soll den Inhalt der Karte zentrieren, tut aber nichts Sichtbares: */
.karte { display: grid; justify-content: center; }

/* Richtig: Inhalt in der Zelle ausrichten. */
.karte { display: grid; justify-items: center; }

Fehler 7 — gap und margin doppelt

.raster { gap: 1rem; }
.karte  { margin: 1rem; }   /* doppelte Lücke, außen ein Rest */

Fehler 8 — Grid für eine einzelne Leiste

/* Drei Buttons in einer Reihe: Flexbox ist kürzer und klarer. */
.knopfreihe { display: flex; gap: 0.5rem; }

Zusammenfassung

EigenschaftEbeneWofür
display: gridContainer macht aus den Kindern ein Raster aus Zeilen und Spalten
grid-template-columnsContainer legt Spaltenzahl und -breite fest, mit fr, repeat(), minmax()
grid-template-rowsContainer legt die Zeilenhöhen fest; fehlende Zeilen entstehen automatisch
grid-auto-rowsContainer Höhe der automatisch angelegten Zeilen
gapContainer Abstand zwischen den Zellen, nichts außen
grid-template-areasContainer Layout als Namenszeichnung; jeder Bereich ein Rechteck
grid-column / grid-row Item Platzierung über Linien (1 / 3) oder span; Endlinie exklusiv
grid-areaItem ordnet das Kind einem benannten Bereich zu
auto-fit + minmax() Container responsive Spaltenzahl ohne Media Query
justify-items / align-items Container Inhalt der Kinder in ihrer Zelle ausrichten
justify-self / align-self Item Ausrichtung eines einzelnen Kindes in seiner Zelle
justify-content / align-content Container das ganze Raster im Container verteilen

Ausblick: Grid trägt das Gerüst, Flexbox das Innenleben. Damit sind die beiden Layout-Werkzeuge komplett — was fehlt, sind Bausteine, die sich wiederholen: Karten, Kopfleisten, Formulare. Genau das liefert Bootstrap, das seinen eigenen Spalten-Mechanismus mitbringt und auf denselben Ideen wie dein Raster steht. Wiederhole dafür KM3-05 — Flexbox (Achsen, gap, order) und KM3-04 — CSS-Selektoren (:last-child, Spezifität, wenn eine Rasterregel nicht greift).
