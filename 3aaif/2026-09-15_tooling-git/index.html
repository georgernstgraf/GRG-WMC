1 · Einstiegsfrage

Du hast deine erste Seite index.html geschrieben. Wie kommt sie auf GitHub — und wie zeigst du sie am Abend deiner Kollegin, ohne sie per Mail zu schicken?

  • Wohin gehört der Code, damit ihn andere sehen und er nicht verloren geht?
  • Wie testest du eine Seite live, während du sie änderst?
  • Was machst du, wenn morgen etwas kaputt ist — wie kommst du zum gestrigen Stand zurück?

Nach dieser Einheit hast du ein Repository, einen Live-Server und ein Rezept (den Dreiklang), mit dem du jede Änderung sicher speicherst.

2 · Ziel-Artefakt: so sieht es am Ende aus

Dein eigenes Repository heißt WMC und enthält index.html. Nach jeder Änderung läuft derselbe Dreiklang — hier die Kurzfassung, die wir gleich Schritt für Schritt aufbauen:

git config --global user.name  "Max Mustermann"
git config --global user.email "max.mustermann@example.com"

git add .
git commit -m "index.html angelegt"
git push
# → im Browser: github.com/<dein-name>/WMC

Der Live Server zeigt dieselbe Seite parallel unter http://127.0.0.1:5500 — und lädt sie bei jedem Speichern neu.

3 · Die Werkzeuge: VS Code als Werkstatt

Programmiert wird nicht in Word. Wir arbeiten in Visual Studio Code (VS Code), einem kostenlosen Editor, und erweitern ihn um drei Extensions:

WerkzeugWozu
VS CodeEditor für HTML/CSS/JS, Terminal, Git-Anzeige, Ordner-Explorer
Live Serverlokaler Mini-Server (Port 5500); Seite lädt bei jedem Speichern automatisch neu
W3C Web Validatorprüft HTML/CSS direkt im Editor auf Standard-Konformität
DevToolsim Browser (F12): HTML-Gerüst, CSS-Regeln, Netzwerk, Konsole

Zwei Links zum Nachschlagen: caniuse.com (welcher Browser unterstützt welches Feature?) und validator.w3.org (Web-Version des Validators).

Extension installieren (Absturz-Kontrolle)

# In VS Code: Ansicht → Erweiterungen (Strg/Cmd + Shift + X)
# Suche „Live Server"          → Install
# Suche „W3C Web Validator"    → Install

Merksatz: Installieren, dann prüfen. Eine Extension, die nicht aktiv ist, hilft niemandem — öffne die Palette (Strg/Cmd + Shift + P) und suche den Befehl, um sie zu testen.

4 · Git: der Dreiklang

Git ist die Versionsverwaltung. Es merkt sich jeden Stand (“Commit”). GitHub ist nur die Online-Ablage dafür — Git funktioniert auch ohne Netz. Eine Änderung wandert in drei Stufen:

StufeBefehlBedeutung
1 · vormerkengit add .Änderungen für den nächsten Commit auswählen
2 · festschreibengit commit -m "…"Stand lokal dauerhaft speichern (mit Nachricht)
3 · hochladengit pushCommits zu GitHub übertragen

Vorher einmalig die Identität setzen (sonst weiß Git nicht, wer committet):

git config --global user.name  "Max Mustermann"
git config --global user.email "max.mustermann@example.com"

git config --global --list   # Kontrolle

Den Zustand schaust du jederzeit an, die Historie mit log:

git status      # was ist geändert? was ist vorgemerkt?
git log --oneline

Repository klonen

Ein vorhandenes Repository holst du mit clone auf deinen Rechner. Das legt den Ordner samt Historie an:

git clone https://github.com/georgernstgraf/GRG-WMC.git
cd GRG-WMC

5 · Ein eigenes Repository auf GitHub

  1. Bei github.com mit der Schul-E-Mail registrieren.
  2. New repository → Name WMC, Sichtbarkeit public, ohne README.
  3. Den angezeigten HTTPS-Link kopieren und lokal verbinden:
git init
git remote add origin https://github.com/<dein-name>/WMC.git
git add .
git commit -m "erste Seite"
git push -u origin main
# -u merkt sich origin/main – danach genügt: git push

Den Link zum Repository schickst du an grafg@spengergasse.at.

6 · Typische Fehler (und wie du sie vermeidest)

  • Committen ohne add: „nothing to commit” — erst vormerken, dann committen.
  • push ohne remote: „No configured push destination” — git remote add origin … fehlt.
  • Falscher Name/E-Mail im Commit: git config --global --list prüfen und korrigieren.
  • Live Server „findet nichts”: es gibt keine geöffnete HTML-Datei bzw. kein index.html im Ordner.
  • file:// statt Server: manche Funktionen (später fetch, Assets) brauchen einen Server. Immer Live Server.
